# 1. Production decision — 73 -> 68 active physical slides

V1 had **73 active slide states**. Applying the presentation-design research changes the count to:

- **68 active physical slides** across the official 4h10 course;
- **7 hidden scenario-bank slides** for ACT 6;
- **1 optional pre-start holding slide** outside the official clock;
- hidden source / troubleshooting appendix remains separate and is not counted yet.

This is not a simplification target. It is the result of asking whether two adjacent states are actually different visual/cognitive objects.

## 1.1 V1 states merged into one physical slide with controlled builds

1. `A0-05 + A0-06` — debrief -> `Ci torniamo alla fine` on one canvas.
2. `A3-04 + A3-05` — partial/total obstruction -> effective/ineffective cough on one progressive decision visual.
3. `A3-13 + A3-14` — outcome resolved vs unresponsive is one decision fork.
4. `A6-05 + A6-06` — renewed-consent framing -> restaurant setting on one slide with context reveal only after consent.
5. `A6-08 + A7-01` — whole-room retrieval naturally continues across the ACT 6/7 boundary on one page.
6. `A7-06 + A7-07` — one final bookend canvas is stronger than two competing endings.

## 1.2 V1 state split

`A4-02` becomes **two slides**:

- adult time-critical CPR/AED evidence;
- pediatric translation / why ventilation matters.

Reason: these are two different conclusions. Combining them violates the one-main-message rule and forces the audience to switch populations while decoding the same visual.

Net result: `73 - 6 + 1 = 68` active physical slides.

## 1.3 Important distinction

**68 physical slides does not mean only 68 visual states.**

Many slides use purposeful builds:

- predict -> reveal;
- state 1 -> state 2;
- algorithm step-by-step;
- de-emphasise previous information;
- correction anchor after learner response.

The physical page count is therefore lower while the attention-control resolution is higher.

# 2. Global deck doctrine

## 2.1 Hierarchy

**learner action / live instructor / live demonstration > relevant visual evidence > minimal words > notes/reference layer.**

The deck supports the event. It is not the event.

## 2.2 Semantic slide types

Use only these slide grammars unless rehearsal reveals a missing job:

- `NARRATIVE` — meaning / transition / bookend;
- `ASSERTION-EVIDENCE` — conclusion + visual proof;
- `DECISION` — branch / algorithm / role assignment;
- `MECHANISM` — anatomy / causal process / physical landmark;
- `RETRIEVAL` — answer intentionally hidden;
- `SCENARIO` — facts only, no answer cue;
- `PRACTICE-HOLD` — operational instruction during learner activity;
- `LIVE-FEED` — QCPR or real-time evidence.

## 2.3 Headline rule

For explanatory slides, default to **message headlines**, not topic labels.

Example:

- not `Distribuzione per età`;
- use `Quasi l'86% dei ricoveri della serie italiana riguardava bambini sotto i 4 anni`.

Exceptions: retrieval, scenario, practice and narrative slides may use questions, commands or minimal context instead of assertions.

## 2.4 Copy rule

The instructor says the explanation. The slide shows what benefits from being seen.

Default on-slide limits:

- narrative: one line or <=12 words preferred;
- assertion-evidence: one sentence headline + visual + source;
- decision: <=6 nodes;
- mechanism: <=5 direct labels;
- scenario: <=4 facts/cues before response;
- practice: <=5 steps / roles;
- ACT 5: one anchor line plus progressive six-step grammar, not six visible paragraphs.

## 2.5 Motion rule

Default:

- **no slide transition / cut**;
- short `Fade` only for deliberate mood/section softening;
- `Appear` / very short `Fade` for progressive disclosure;
- no fly-in, bounce, spin, decorative zoom or random direction;
- no looping GIF in V1 production;
- no prerecorded procedure video in the baseline deck where a live demonstration is superior.

Candidate for controlled animation:

- airway / airflow / obstruction mechanism on S19.

Optional Morph only if it clarifies spatial continuity and remains invisible as an effect. Do not use Morph as branding decoration.

## 2.6 Screen-attention rule

Each slide below declares a primary gaze target:

- `SCREEN` — the visual itself carries information;
- `INSTRUCTOR` — screen is supportive/minimal;
- `MANIKIN` — live physical skill is primary;
- `PEER / VOLUNTEER` — scenario/human interaction is primary;
- `WORKSHEET` — participant writes/acts off-screen;
- `LIVE QCPR` — application feed is primary.

When gaze target is not `SCREEN`, the slide must visually recede.

## 2.7 Section orientation

Do not add separate agenda slides.

Instead, the first slide of each major act carries a subtle section marker and a compact five-stage journey cue where useful:

**PROBLEMA -> METODO -> SKILL CORE -> ALTRE EMERGENZE -> APPLICAZIONE / CASA**

Only the current stage is emphasized. Do not persist this strip on dense technical slides.

## 2.8 Colour / meaning

Colour is functional, not decorative.

Working semantic roles for later design-system task:

- Formalife brand accent — structure / current focus;
- danger / `NON FARE` — one consistent warning colour;
- emergency / 112 — one consistent emergency signal;
- safe/continue/appropriate branch — one consistent positive-action code;
- neutral — everything not currently relevant.

Never rely on colour alone: pair colour with label, icon, shape or position.

# 18. Rehearsal validation specific to V2

The first rehearsal should evaluate the **slide system**, not merely content timing.

For every slide record:

1. did it direct attention to the right place?;
2. did it expose the answer before retrieval?;
3. did the build make the explanation clearer or merely slower?;
4. did anyone read instead of listen/watch?;
5. was the message legible from the back?;
6. did the slide add a new cognitive job or duplicate the previous one?;
7. during demo/practice, did participants keep looking at the screen when they should watch the instructor/manikin?;
8. did ACT 1 evidence remain understandable without verbal caveat overload?;
9. did ACT 5 grammar feel repetitive in a helpful way rather than visually monotonous?;
10. did S67 disappear operationally before S68, leaving the final close clean?;
11. did the merged slides function as coherent progressive states?;

# 20. Current production conclusion

The recommended baseline is now:

**68 active physical slides + 7 hidden scenario-bank slides + 1 optional pre-start slide.**

This is not “fewer slides for the sake of fewer slides.”

The V2 count is lower because repeated cognitive jobs are consolidated into progressive builds, while one overloaded CPR evidence state is split because it contains two distinct conclusions.

The protected rule for future production is:

**do not optimise slide count; optimise attention, comprehension, retrieval and live execution.**
