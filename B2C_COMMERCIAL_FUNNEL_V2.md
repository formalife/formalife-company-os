# Formalife B2C Commercial Funnel V2

Status: PROVISIONAL TARGET ARCHITECTURE — founder-directed; offer roles require validation
Date: 2026-09-21

Purpose: define the **ideal direct-to-consumer Formalife funnel** from first attention to repeat purchase, referral and lifecycle reactivation, without forcing the design around products that happen to exist today.

This document supersedes `CORE_COMMERCIAL_FUNNEL_V1.md` for B2C architecture.

It does **not** mean every offer must be built now. `FORMALIFE_BUILD_SEQUENCE.md` still governs execution order.

## 1. Founder direction now in force

The B2C funnel must be designed zero-based from the customer journey and economics, not from the current asset list.

Founder direction:

- **Light / Serata Anti-Panico is not part of the direct B2C funnel**;
- Light belongs to the **B2B / B2B2C partner-hosted channel**;
- the B2C funnel must include the offers and stages that a strong mature consumer system actually needs, even when those offers do not exist yet;
- existing products remain assets, not mandatory steps.

## 2. Governing doctrine

The funnel must obey five rules.

### Rule 1 — state before step

A prospect should receive the next action appropriate to their current awareness, intent, timing and prior purchases.

A high-intent parent must not be forced through a lead magnet, Guide or low-ticket product before buying the core offer.

### Rule 2 — every offer must have a distinct job

No offer exists merely to create another checkout.

A lower-level product must be complete enough to create real value. A higher-level product must add materially different value rather than charging again for the same thing.

### Rule 3 — the funnel is judged on customer economics

Lead volume, opt-ins and first sales are intermediate signals.

The economic chain is:

**source -> complete acquisition cost -> first transaction contribution -> core conversion -> second purchase -> contribution over time -> payback.**

### Rule 4 — proof and delivery are inside the funnel

The commercial promise must survive the product experience.

Proof is created by delivery and then returned to acquisition through testimonials, demonstrations, referrals and authority.

### Rule 5 — lifecycle is not forced continuity

Formalife should preserve a legitimate `WAITING FOR TRIGGER` state.

A customer who has no current safety need is not automatically churned, dormant or ready for another promotion.

## 3. Economic job of the B2C funnel

The mature B2C funnel should do five economic jobs:

1. capture active demand efficiently;
2. educate and convert latent/problem-aware demand;
3. create a first paid relationship at more than one price/commitment level;
4. move a sufficient portion of customers into higher-value core and specialist products;
5. preserve the relationship until a real new trigger creates another monetizable need.

The funnel is therefore not:

**traffic -> Guide -> Full Course -> BLSD.**

It is:

**demand state -> appropriate value exchange -> first transaction or direct core -> delivery -> next relevant value -> lifecycle / referral.**

## 4. Master B2C funnel

### Direct high-intent lane

**active search / referral / returning prospect -> proof + offer page -> Digital Core OR Live Flagship OR Hybrid Bundle -> delivery -> specialist depth / lifecycle / referral**

### Problem-aware lane

**content / paid social / organic discovery -> free high-value asset -> owned contact -> education/proof sequence -> Guide OR Digital Core -> Live Flagship / Hybrid when relevant -> back-end**

### Low-awareness / latent lane

**trigger-led content/ad -> open useful resource -> gated next-value offer when appropriate -> education -> first paid offer -> core**

### Existing customer lane

**customer record -> actual new trigger / skill-decay / caregiver change -> relevant next offer -> delivery -> updated customer state**

These lanes converge into one customer record. They are not separate databases.

## 5. Phase A — demand creation and capture

### A1. Active demand

Examples:

- parent searching for a pediatric first-aid / choking / emergency-preparedness course;
- parent referred by another customer;
- returning prospect asking for date, price or availability;
- parent who already knows Formalife and is ready to decide.

Primary objective:

**do not create unnecessary steps.**

Primary CTA:

**buy/book the most appropriate core offer.**

Likely core choices in the mature system:

- Digital Emergency-Preparedness Flagship;
- Live Full Course;
- Hybrid Digital + Live package.

### A2. Problem-aware demand

Examples:

- starting solids makes choking salient;
- parent recognizes a preparedness gap but is not yet shopping for a course;
- parent consumes safety information after a scare, question or life-stage transition.

Primary objective:

**turn concern into informed action without manufacturing fear.**

Primary CTA can be:

- use/download a focused resource;
- enter a useful mini-training;
- buy the Guide;
- buy a relevant digital product if readiness is already high enough.

### A3. Latent demand

The prospect is in the target market but the issue is not yet high priority.

Marketing job:

- use real life-stage triggers;
- make consequences understandable and proportionate;
- create useful value before asking for a large commitment;
- move only responsive prospects deeper.

Do not use shock, invented emergencies or false urgency.

## 6. Phase B — free-value architecture

Formalife should have both **ungated** and **gated** free value.

### Offer F0 — Open Safety Utility / Resource

Status: TARGET CAPABILITY — exact product not yet chosen.

Job:

- solve a small but recurring safety question immediately;
- create search/social sharing and repeat visits;
- demonstrate usefulness before asking for data;
- expose the next relevant problem naturally.

Examples of format, not approved clinical products:

- practical reference tool;
- decision checklist;
- short expert explainer;
- stage-specific safety resource;
- searchable safety reference.

CTA:

**use the resource; optionally request/save a more valuable next asset.**

### Offer F1 — High-intent Lead Offer

Status: TARGET CAPABILITY.

Job:

- exchange more specific value for a lawful contact/permission;
- identify the trigger/need;
- create the first owned relationship.

Possible formats:

- focused checklist/toolkit;
- mini-class / expert video;
- short problem-specific guide;
- stage-specific preparation plan.

The lead offer should capture only data that changes routing, for example source, broad caregiver role or relevant life-stage trigger where useful and lawful.

CTA:

**consume the asset -> take the next appropriate paid or educational step.**

### Optional activation event

A free live/digital expert session can exist when it materially improves conversion or trust.

It is **not** a mandatory funnel component and should not become a free version of the paid flagship.

## 7. Phase C — first paid relationship

### Offer P1 — Paid Information Front-End: Guide / Book

Current asset:

- Guida Anti-Panico al Soffocamento Pediatrico;
- EUR 19.90 current canonical price.

Strategic job:

- turn an identified prospect into a buyer;
- provide durable reference value;
- build authority through a real paid product;
- identify buyers willing to invest in preparedness;
- create a legitimate bridge toward deeper education.

It is not mandatory before Digital or Live.

#### Candidate order-bump tests — HYPOTHESIS

Only if the economics support them:

- additional caregiver copy;
- family/reference pack;
- another low-cost companion that directly increases use of the Guide.

Do not add unrelated merchandise merely to increase AOV.

#### Training Credit — HYPOTHESIS FOR V2

The current Guide-to-Full Training Credit can be tested as a broader **credit toward the next core learning level** only if economics support it.

Possible future applications:

- Guide -> Digital Core;
- Guide -> Live Flagship;
- Guide -> Hybrid Bundle.

This is not yet a founder decision on credit amount or rules.

The purpose is to reduce the feeling of paying twice, not to discount indiscriminately.

## 8. Phase D — core monetization

The mature B2C system should have **two core delivery modes**, not one forced path.

### Offer C1 — Digital Emergency-Preparedness Flagship

Status: TARGET BUILD — not current offer.

Job:

- provide substantial standalone consumer value nationally;
- serve families who cannot or do not yet want live attendance;
- create scalable gross contribution;
- provide long-lived reference/replay where scientifically appropriate;
- create a natural bridge toward live practice.

Requirements:

- real standalone result;
- visible scientific/human authority;
- strong production quality;
- long-lived or lifetime access where sustainable;
- structured reference materials;
- clear boundary between what can be learned digitally and what benefits materially from supervised practice.

It must not be a deliberately incomplete teaser for the live course.

### Offer C2 — Live Full Course: Pediatric Safety & Emergency Preparedness

Status: CURRENT/REBUILDING CORE.

Current commercial architecture:

- EUR 80 Single;
- EUR 120 Couple;
- maximum 12 participants;
- broader parent-first pediatric safety/emergency preparedness;
- substantial practical depth;
- choking remains a signature block;
- meaningful pediatric resuscitation introduction;
- attendance certificate, not professional certification.

Strategic job:

- create the strongest practical Formalife experience;
- produce proof, referral and authority;
- deliver value that cannot be replicated by passive content alone;
- expose distinct higher-depth needs without making the live course incomplete.

A high-intent local prospect may buy this as their **first transaction**.

### Offer C3 — Hybrid Digital + Live Preparedness Bundle

Status: TARGET OFFER HYPOTHESIS.

Job:

- combine durable digital/reference learning with supervised live practice;
- increase completeness and AOV without inventing another curriculum;
- allow theory/reference to live outside the limited classroom attention budget;
- create a clear premium option for customers who want both convenience and practice.

This is a packaging hypothesis, not a requirement that Digital and Live always be sold together.

The bundle must be economically better for Formalife than simply discounting two independent products.

## 9. Core upsell/downsell architecture

### If the prospect wants Live but geography/time is the barrier

Downsell/alternative:

**Digital Core.**

### If the prospect wants more than Digital and values supervised practice

Upsell:

**Live Flagship or Hybrid upgrade.**

### If Digital is still too much commitment

Downsell:

**Guide / paid reference product.**

### If the Guide is too much commitment

Fallback:

**free value + permission + wait.**

### If the customer wants both Digital and Live

Offer:

**Hybrid Bundle**, if validated.

The system should not automatically discount the higher product when someone declines. Diagnose the barrier first.

## 10. Phase E — specialist and premium back-end

### Offer B1 — BLSD Formalife, non-certified

Status: FOUNDER-DECIDED FUTURE PRODUCT.

Job:

- intensive deliberate practice;
- scenarios;
- deeper CPR/AED work;
- repetition and correction;
- refresh/household-sharing logic.

This is **specialist depth**, not the mandatory next step after every Full Course.

Trigger:

**customer explicitly wants greater resuscitation mastery.**

### Offer B2 — Private Family / Caregiver Intensive

Status: HYPOTHESIS — existing parked capability, economics unproven.

Job:

- serve households wanting multiple caregivers trained together;
- create a premium, high-convenience format;
- potentially include parents, grandparents and babysitter/nanny in one practical session;
- monetize customers for whom convenience/customization is worth more than public-class pricing.

This should exist only if:

- price supports instructor/travel/time cost;
- customer demand is real;
- delivery is sufficiently standardized;
- it does not consume capacity better used elsewhere.

### Offer B3 — Additional Caregiver / Family Extension

Status: TARGET OFFER ROLE.

Job:

- solve the real problem that the child is cared for by more than one adult;
- create a second transaction or bundle without inventing a new safety need.

Possible forms:

- extra live seat;
- digital family access;
- caregiver bundle;
- gift/voucher;
- private family upgrade.

Exact mechanics require economics and consent/access design.

## 11. Phase F — horizontal lifecycle cross-sell

These are **not immediate upsells**.

They activate only when a real new trigger appears.

Candidate future product families already mapped in Layer 2 include:

- Newborn Safety & Safe Sleep;
- Starting Solids / Feeding Safety through specialist partnership;
- Sickness & Red Flags;
- Home Safety & Babyproofing;
- Water Safety;
- Car Seat Safety through specialist competence;
- Food Allergy & Anaphylaxis Preparedness;
- Child + Pet Safety.

The commercial rule is:

**new trigger -> new need state -> relevant mini-funnel -> relevant product.**

Do not email every adjacent course to every customer.

## 12. Phase G — refresh, reassessment and continuity

### Offer R1 — Practical Refresh / Reassessment

Status: FUTURE PRODUCT ROLE.

Job:

- counter skill decay where practice matters;
- give prior customers a reason to rehearse without repurchasing the same full course;
- create evidence of ongoing competence/comfort at the consumer level without misrepresenting certification.

Trigger can include:

- elapsed time;
- customer self-reported loss of confidence;
- new caregiver;
- updated guidance/product version;
- new sibling or care context.

### Offer R2 — Annual Safety Pass / Membership

Status: CONDITIONAL FUTURE HYPOTHESIS.

Do **not** build this merely because subscriptions are attractive.

It becomes rational only if Formalife can continuously deliver enough recurring value, potentially through:

- meaningful maintained digital library;
- updated reference material;
- stage-based pathways;
- expert Q&A;
- refresh benefit;
- caregiver extensions;
- new digital modules/member pricing.

If recurring usage/value is weak, do not create a membership.

## 13. Phase H — referral and advocacy

Referral begins **after** a strong experience, not at first contact.

### Referral trigger

- course/product successfully delivered;
- satisfaction explicitly positive;
- customer can identify who else would benefit.

### Referral offers/mechanisms — TEST OPTIONS

- easy sharing of genuinely useful free resources;
- gift Guide / extra Guide copy;
- caregiver invitation;
- referral credit;
- bring-a-caregiver / family upgrade;
- gift voucher.

The incentive must be cheaper than acquiring an equivalent customer elsewhere and must not damage trust.

Track:

**referrer -> referred customer -> purchases -> contribution.**

## 14. Nurture and follow-up system

A lead entering the database should not receive an endless generic newsletter.

The funnel should use state-specific sequences.

### New problem-aware lead

Sequence job:

1. deliver promised value;
2. establish relevance and authority;
3. explain the real consequence/problem without exaggeration;
4. show the available solution categories;
5. introduce Formalife's operational difference once it is genuinely defined;
6. use relevant proof;
7. present the appropriate offer/CTA;
8. route behavior rather than forcing a fixed timer.

### Front-end buyer

Sequence job:

- onboarding/fulfilment;
- usage encouragement;
- distinct reason for deeper learning;
- next core offer;
- credit/upgrade explanation if applicable;
- stop selling what they already bought.

### Digital buyer

Sequence job:

- activation/completion;
- usage signals;
- explain what supervised practice adds;
- Live/Hybrid offer to customers showing the relevant need;
- otherwise lifecycle/waiting state.

### Live customer

Sequence job:

- preparation/logistics;
- attendance/completion;
- post-course reference;
- feedback/proof/referral;
- identify depth or lifecycle need;
- WAITING FOR TRIGGER when no need exists.

### Abandoned cart / almost buyer

Use:

- reminder;
- FAQ/objection resolution;
- relevant proof;
- human help where useful;
- appropriate downsell only if the barrier matches.

Do not solve every abandonment with a discount.

## 15. Proof architecture by stage

### Free/lead stage

Need to prove:

- usefulness;
- credibility;
- relevance to the parent problem.

### Guide / information front-end

Need to prove:

- this is a serious usable reference product;
- author/scientific provenance is credible;
- the content is worth paying for rather than just another generic PDF.

### Digital Core

Need to prove:

- substantive learning value;
- quality and depth;
- human/scientific authority;
- usability/reference value;
- customer outcomes/experience once real cohorts exist.

### Live Flagship

Need to prove:

- real supervised practice;
- parent-first relevance;
- scientific responsibility;
- specific customer experiences;
- operational difference versus credible alternatives once defined.

### BLSD / premium depth

Need to prove:

- materially deeper practice/repetition;
- why it is different from the Full Course;
- why non-certification is appropriate for the learning job;
- customer value beyond credential acquisition.

Historical proof must not be stretched to prove materially new products before those products have been delivered.

## 16. Pricing architecture

Current known prices remain:

- Guide: EUR 19.90;
- Full Course: EUR 80 Single / EUR 120 Couple.

No price is assigned here to Digital, Hybrid, BLSD Formalife, Private Family or future verticals.

Pricing must be derived from:

- distinct customer job;
- perceived and delivered value;
- credible alternatives;
- contribution margin;
- complete CAC;
- price relationship across the ladder;
- capacity/cost-to-serve.

Do not assume mechanically that every higher stage must be only slightly more expensive than the previous one.

## 17. Customer record / state machine

Minimum future customer-state model:

**VISITOR -> IDENTIFIED LEAD -> FRONT-END BUYER -> CORE DIGITAL BUYER / LIVE CUSTOMER -> SECOND-PURCHASE CUSTOMER -> WAITING FOR TRIGGER -> REACTIVATED -> ADVOCATE**

Parallel attributes should include, where lawful/useful:

- source/campaign;
- trigger/need;
- awareness/intent state;
- caregiver role;
- relevant broad life stage;
- products purchased;
- completion/attendance;
- next plausible need;
- consent state;
- referral source/behavior.

A click or open is a signal, not proof of buying intent.

## 18. Funnel scorecard

### Acquisition

- traffic/source volume;
- cost per identified lead where relevant;
- lead-offer conversion;
- source-specific buyer conversion.

### First transaction

- Guide/front-end conversion;
- average order value;
- contribution on first transaction;
- cost per first buyer.

### Core conversion

- lead -> Digital;
- Guide -> Digital;
- lead/Guide -> Live;
- Digital -> Live/Hybrid;
- direct high-intent -> Live;
- Full Course fill rate;
- normalized contribution per edition;
- contribution per core buyer.

### Back-end

- second-purchase rate;
- time to second purchase;
- BLSD attach rate among relevant customers;
- caregiver/family expansion rate;
- refresh rate when the product exists.

### Relationship economics

- complete CAC by source;
- cumulative contribution by cohort;
- payback period;
- revenue/contribution per customer/family over time;
- referral-sourced contribution;
- capacity consumed per euro of contribution.

## 19. Funnel gates

### Gate 1 — positioning / offer

Before cold scale, Formalife must be able to explain and operationally deliver why the target parent should choose its core product over credible alternatives.

### Gate 2 — product/scientific readiness

No clinical promise or rebuilt Full Course is publicly scaled before scientific validation.

### Gate 3 — first core economics

At least one core B2C path must show repeatable positive or intentionally recoverable economics before more front-end complexity is added.

### Gate 4 — front-end justification

Guide, free assets, order bumps and other front-end steps remain only if they improve customer acquisition economics, qualification, authority, payback or downstream conversion.

### Gate 5 — digital proof

The Digital Core must prove contribution and customer usage before Formalife builds a large digital library.

### Gate 6 — back-end proof

Do not use theoretical LTV to justify CAC until second purchases and timing are observed.

## 20. Build order inside this target funnel

This is the **target architecture**, but the implementation order should remain narrow.

### Now

1. finish sellable/scientifically valid Live Full Course;
2. make direct B2C demand -> Full Course measurable;
3. make Guide a measurable optional paid front-end;
4. build proof, follow-up, cart recovery, referral and customer-state tracking around those working offers.

### Next

5. build one substantial Digital Core;
6. test Digital direct acquisition;
7. test Digital -> Live and Hybrid packaging;
8. compare economics of Guide-first, Digital-first and direct-Live paths.

### Then

9. build BLSD Formalife depth;
10. test caregiver/private-family premium offers;
11. activate lifecycle mini-funnels only when adjacent products are real;
12. build recurring utility/account infrastructure around products that already monetize.

### Later / conditional

13. refresh/reassessment;
14. continuity pass/membership only if recurring value is proven;
15. wider catalog only after existing paths are economically legible.

## 21. What this funnel deliberately excludes

- Light as a direct B2C offer;
- mandatory Guide-before-core behavior;
- fake scarcity;
- automatic discounts for non-buyers;
- membership before recurring value exists;
- cross-selling every product to every customer;
- using theoretical future LTV to excuse weak current economics;
- building many digital products before one works;
- using medical fear as a substitute for proof;
- treating certification as the meaning of the consumer brand.

## 24. Revision condition

Revise this architecture when real B2C evidence shows that an offer role does not improve economics, a stronger route consistently outperforms it, a product job overlaps enough to confuse customers, or delivery/capacity makes the theoretical path unattractive.

The rule is:

**keep the customer journey sophisticated; keep the number of economically unproven variables small.**
