# 1. Execution rules

## 1.1 SAY / SHOW / CLICK rule

The instructor must never click merely because a sentence ended.

A click occurs only when one of these jobs is complete:

1. the learner has committed to an answer;
2. the current visual evidence has been interpreted;
3. the instructor is moving to a materially different state;
4. the screen must hand attention back to the instructor/manikin;
5. the same mental object must visibly transform via Morph.

## 1.2 Reveal rule

If the instructor is asking a question, **the answer is not visible yet**.

Order:

**question -> learner commitment -> reveal -> short correction/meaning -> next state.**

## 1.3 Demo rule

Before a full-speed physical demonstration:

**screen simplifies/dims -> instructor says where to look -> demo -> screen returns for deconstruction.**

Do not leave technique bullets visible during the full-speed demo.

## 1.4 Morph rule

Use Morph when the participant should perceive:

**“this is the same object/system, but its state or emphasis has changed.”**

Preferred Morph families:

- FVA;
- pediatric airway -> obstruction -> observable state -> decision;
- child -> infant shared decision skeleton;
- choking unresolved branch -> 112/CPR;
- pediatric CPR translation -> algorithm -> rescuer roles;
- paired ACT 5 recognition -> action slides;
- final Mirror Test -> before/after debrief.

Use Cut/Fade where semantic separation matters.

## 1.5 Build notation

Within each slide:

- `B0` = first visible state;
- `B1`, `B2`... = subsequent click/reveal states;
- `M` = Morph to next physical slide;
- `F` = Fade/Cut to next physical slide.

# 14. Rehearsal test for SAY / SHOW / CLICK

For each slide during rehearsal, observer records:

- did the instructor reach the verbal trigger before the relevant visual appeared?;
- did any answer appear before learner commitment?;
- did a click occur while participants were still looking elsewhere?;
- did Morph clarify “same object, new state” or attract attention to itself?;
- did the instructor need to say “ignore what's on the slide for a moment”? If yes, synchronization failed;
- did any visual remain after its teaching job was finished?;
- did a slide require verbal explanation merely to understand its layout?;
- did any build slow the instructor without adding comprehension?;
- did a transition create the false impression that two datasets/populations were directly continuous?;
- during demo/practice, did the screen recede enough?;
- did the official final image remain S68 with no operational restart?

- `SYNC KEEP`;
